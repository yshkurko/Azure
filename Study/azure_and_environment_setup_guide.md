# Руководство по настройке аккаунта Azure, сети и окружения

Данное руководство составлено на основе нашей текущей сессии и включает в себя пошаговые инструкции по авторизации в VS Code, управлению подписками Azure, созданию сетевой инфраструктуры и устранению системных ошибок.

---

## 1. Подключение аккаунта GitHub в VS Code

Для работы с расширениями (например, GitHub Copilot) и синхронизации:

1. Откройте VS Code и нажмите на иконку **аккаунта / шестеренки** в левом нижнем углу интерфейса.
2. Выберите **Sign in to Sync Settings** или выберите пункт **GitHub** в выпадающем списке.
3. В появившемся окне браузера подтвердите доступ для *Visual Studio Code* (**Authorize Visual Studio Code**).
4. Вернитесь в редактор — ваш аккаунт будет успешно подключен.

---

## 2. Управление подписками Azure (Portal & CLI)

Если в мастере настройки ресурсов список подписок пуст или требует уточнения деталей:

### Как проверить подписку в портале Azure:
1. Перейдите на [portal.azure.com](https://portal.azure.com).
2. Введите в поиске **Subscriptions** и выберите нужную подписку (например, *Azure subscription 1*).
3. В блоке **Essentials** проверьте тип плана (в современных аккаунтах это обычно **Azure Plan**).

### Как узнать Offer ID через Azure Cloud Shell:
1. Нажмите на иконку терминала **`>_`** в верхней панели портала Azure.
2. Выполните команду для просмотра сведений о подписке:
   ```bash
   az account show --output json
   ```
3. Найдите в выводе параметр **`offerId`** (или `quotaId` через REST API), содержащий код вашего тарифного плана.

## 3. Настройка виртуальной сети (Virtual Network) в Azure

Если при создании сервисов вы получаете ошибку *«No Results were found»* в поле **Resource group** или **Virtual network**, необходимо предварительно создать инфраструктуру:

1. **Создание группы ресурсов**:
   * В поиске Azure найдите **Resource groups** $\rightarrow$ **Create**.
   * Укажите имя (например, `rg-network`) и выберите регион.
2. **Создание виртуальной сети**:
   * В поиске найдите **Virtual networks** $\rightarrow$ **Create**.
   * Выберите созданную группу ресурсов `rg-network` и задайте имя (например, `vnet-main`).
   * Перейдите на вкладку **Address space** / **IP Addresses**, убедитесь в наличии подсети по умолчанию (`default`, диапазон вроде `10.0.0.0/24`).
   * Нажмите **Review + create** $\rightarrow$ **Create**.
3. **Применение в мастере**:
   * Перезагрузите/переоткройте окно мастера настройки — созданные ресурсы успешно отобразятся в выпадающих списках.

## 4. Решение проблемы с запуском npm скриптов в PowerShell

Если при вызове команд `npm` в Windows PowerShell возникает ошибка безопасности (`... cannot be loaded because running scripts is disabled on this system`):

1. Откройте **PowerShell от имени Администратора** (кликните правой кнопкой мыши по значку PowerShell $\rightarrow$ Запуск от имени администратора).
2. Выполните команду для разрешения выполнения скриптов текущим пользователем:
   ```powershell
   Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
   ```
3. Подтвердите изменения, нажав клавишу **`Y`** (Yes) и `Enter`.
4. Закройте окно администратора и проверьте работу в обычном терминале:
   ```powershell
   npm --version
   ```
